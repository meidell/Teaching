Email alert for student messages

When this is on, every message a student sends you from any course — a direct message, the cohort thread, or a group you made — is also emailed to you, with a link straight to the thread. Messages between students are never forwarded. The message itself is always stored on the site whether this is on or off; the email is an extra.
— Reading the current setting…
The endpoint is a Google Apps Script web app that you deploy once from your own Google account — it is the only thing that knows your address. Steps and the script are below; paste the URL it gives you here and switch the alert on.
Set up the endpoint (once, about five minutes)
  1. Go to script.google.com, signed in as the Gmail address you want the alerts at, and create a New project.
  2. Replace everything in the editor with the script below (Copy script). If you want alerts at another address, change TO on the first line.
  3. Deploy → New deployment → Web app. Execute as: Me. Who has access: Anyone. Click Deploy and authorise it when asked (it only needs permission to send mail as you).
  4. Copy the Web app URL (it ends in /exec), paste it in the Endpoint box above, Save, then Send a test email and check your inbox.
  5. Switch the alert on. To stop the emails, switch it off here — no need to touch the script. If you ever edit the script, deploy it again as a new version of the same deployment so the URL stays.
Rate-limited to 40 emails an hour inside the script, so a loop or a prank cannot flood you.
var TO = 'janerik.meidell@gmail.com';   // where the alerts go
var MAX_PER_HOUR = 40;                   // a ceiling, not a target

function doPost(e) {
  try {
    var d = JSON.parse((e && e.postData && e.postData.contents) || '{}');
    var cache = CacheService.getScriptCache();
    var n = Number(cache.get('n') || 0);
    if (n >= MAX_PER_HOUR) return out('rate-limited');
    cache.put('n', String(n + 1), 3600);

    var s = function (v, max) { return String(v == null ? '' : v).slice(0, max); };
    var course = s(d.course || '?', 40), name = s(d.name || '?', 80), tid = s(d.tid, 80);
    var txt = s(d.txt, 1500), link = s(d.link, 300), page = s(d.page, 300);
    var where = tid.indexOf('dm-') === 0 ? 'in a direct message' : 'in thread ' + tid;
    var subject = (d.test ? '[test] ' : '') + '[' + course + '] Message from ' + name;
    var body = name + ' wrote to you ' + where + ' (' + course + '):\n\n' + txt +
               '\n\n— Reply here: ' + link + (page ? '\n(sent from ' + page + ')' : '');
    MailApp.sendEmail({ to: TO, subject: subject, body: body });
    return out('ok');
  } catch (err) {
    return out('error: ' + err);
  }
}
function doGet() { return out('notify endpoint up'); }
function out(t) { return ContentService.createTextOutput(t); }

Push notifications · your phone and your Mac

A student message reaches your devices as a notification, with the message and a link to the thread. The same sender pushes to students who turn it on at /shared/notifications.html: an announcement you post, a reply you send. Set up once; then each device is one button.
— Reading the current setting…
The sender is a Cloudflare Worker you deploy once from the push/ folder of the repo (five commands, below). Saving fetches its public key and stores both in _site/push.
Set up the sender (once, about ten minutes)
  1. Open a terminal in the repo's push/ folder. A free Cloudflare account is enough; npx downloads the tool.
  2. npx wrangler login — opens the browser once.
  3. npx wrangler kv namespace create SUBS — prints an id; paste it into wrangler.toml where it says so.
  4. node keys.mjs — prints the private key as one JSON line. Then npx wrangler secret put VAPID_PRIVATE_JWK and paste that line when asked. This is the only secret; it never goes in the repo.
  5. npx wrangler deploy — prints the worker URL. Paste it above, Save, switch on, Enable on this device, Send a test.
The _site/push rules block must be deployed first (firebase-database-rules.json), like every rules change. To change the worker later: edit push/worker.js and run npx wrangler deploy again; the URL stays.
On your iPhone
  1. Open this page in Safari (not from inside another app).
  2. Tap Share → Add to Home Screen → Add. iPhones receive web notifications only from a site on the Home Screen.
  3. Open it from the Home Screen icon. It has its own storage, so unlock the gate and sign in once more there.
  4. Press Enable on this device, allow notifications, then Send a test.
On a Mac, Safari, Chrome, Edge and Firefox all work from a normal tab — press Enable on this device here. If Chrome's notifications never appear, check macOS System Settings → Notifications → Google Chrome.
