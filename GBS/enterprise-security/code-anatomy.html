Session 4 · The arsenal · what the attacker's code actually looks like

What the code looks like

Two questions come up every time: a person does not sit and type thousands of passwords, so what does the code that does it look like? And when we say "malware", what is actually inside it? This page answers both by showing the shape of the code — enough to understand it — and then, for every part, how a defender sees it. The point you keep is that each piece has a known detection, named beside it.

What is on this page, and what is not. The code below is illustrative skeleton: it shows the structure, and every line that would do real harm — the network request, the payload, the way malware copies itself — is left as a plain-English comment, not written out. It is here to be read and understood, not run. Writing or pointing a working version of any of this at a system you do not own is a crime in Switzerland and almost everywhere else; that boundary is part of the profession, not a footnote to it.

1 · A person does not type the guesses — a loop does

In demo 1 the guesses appeared one after another. Nobody typed them. The whole "tool" is a short loop: take a list of likely passwords, try each one, stop when one works. That is why the guessing is fast, and it is why the student's instinct — "surely someone notices" — points straight at the defence.

illustrative — the shape of a guessing tool, not a working one
# a list of common passwords — real lists hold tens of millions of lines passwords = load_list("common-passwords.txt") for pw in passwords: ok = try_login("arvane_ops", pw) # <-- in a real tool THIS sends one login request # over the network. We leave it unwritten. if ok: print("found the password:", pw) break

Read it once and the whole idea is there. The loop is the attacker. A human types nothing. The only line that reaches the outside world is try_login(...), one request per guess — and we deliberately do not write what is inside it, because the loop is the lesson and the request is the weapon. How fast the attack runs is simply how fast that one request comes back, which is set by the server, not by the password box.

What the server sees

Here is the same attack from the defender's side — the login server's log during one minute of that loop:

12:04:01 POST /login user=arvane_ops from 203.0.113.9 FAIL 12:04:01 POST /login user=arvane_ops from 203.0.113.9 FAIL 12:04:01 POST /login user=arvane_ops from 203.0.113.9 FAIL 12:04:01 POST /login user=arvane_ops from 203.0.113.9 FAIL … 3,900 more in this minute, all the same account, all from one address …

No human logs in four thousand times a minute. The pattern is the detection: many failures, one account, one source, in seconds. A defender does not need to see the attacker's code to catch this; they need to watch their own logs.

The lessonThe attack is a loop around one network request. You cannot stop someone writing the loop, so the defence lives where the requests arrive — on the server — and in the log pattern the loop cannot hide.
The defences, in order of effectLock or slow the account after a few failures (the loop stalls or trips an alert) · require a second factor so a guessed password alone is not enough · store passwords under a slow salted hash so a stolen file is not a shortcut (demo 2) · and watch the logs for the burst above. Any one of these turns the loop from a threat into a line in a report.

2 · What malware is made of — four parts

"Malware" is not one thing. Almost every piece, from a simple virus to NotPetya, is built from the same four parts. Seeing the parts is what lets you reason about a new one you have never met: you ask which part is which, and each part has a known defence. Below, each part is one line of skeleton — the harmful body replaced by a comment — then how it works in the wild, how it looked in a real case, and what catches it.

illustrative anatomy — every harmful step is left as a comment, not code
# This is a LABELLED SKELETON, not a program. Nothing here is implemented. def deliver(): # how it arrives: an email attachment, a fake update, a USB stick ... def persist(): # how it survives a reboot: add itself to the system's startup list ... def payload(): # the harmful act: encrypt files, wipe the disk, or steal data ... def call_home(): # open ONE outbound connection to the attacker (this is demo 3) ...
PART 1 Delivery & trigger — how it gets in, and what sets it off
def deliver(): # arrive and run: a clicked attachment, a booby-trapped update, a worm that needs no click
In the wildMost malware is invited in: someone opens an attachment or runs a fake installer. The dangerous kind is a worm, which uses a software flaw to spread with no click at all.
In WannaCryMay 2017. No click. It used a Windows network flaw (EternalBlue) to copy itself from one unpatched machine to the next, across the world in hours.
What catches itPatching the flaw it rides (Part 1 of the patch-gap lesson) · blocking macros and unknown attachments · controlling USB devices · network segments so one infected machine cannot reach every other.
PART 2 Persistence — how it survives a reboot
def persist(): # register to run at every startup — a service, a scheduled task, a startup entry
In the wildA reboot clears a program from memory. To last, malware writes itself into one of the handful of places the system runs automatically at boot — a service, a scheduled task, a registry startup key.
In WannaCryIt installed itself as a Windows service so it restarted with the machine and kept encrypting.
What catches itEDR (endpoint detection) watches exactly these startup locations and flags a new service or task that no admin created — one of the loudest signals a defender has.
PART 3 Payload — the harmful act
def payload(): # the point of the whole thing: encrypt files for ransom, wipe the disk, or quietly steal data
In the wildThe payload is why the malware exists. Ransomware encrypts your files and sells back the key. A wiper destroys them. Spyware copies data out. Same anatomy, different payload.
In WannaCryRansomware: it encrypted documents on each machine and demanded about $300 in Bitcoin. NotPetya (the course's running case) looked identical but its payload was a wiper — it never meant to give the files back.
What catches itThe payload is fast and visible: thousands of files changed in seconds, unusual disk writes, backups being deleted. EDR and file-monitoring flag the rate. Offline backups are what let you recover anyway.
PART 4 Call-home (command & control) — the connection back
def call_home(): # open one outbound connection to the attacker — report in, fetch orders, send stolen data
In the wildMost malware phones home: to report it landed, to fetch the next instruction, or to send data out. Mechanically this is exactly demo 3 — one outbound socket. The malicious part is not clever; it is the direction and the destination.
In WannaCryIt checked for a specific web address first — the "kill switch" a researcher registered, which stopped the outbreak. Other malware uses this same channel to take live orders from the attacker.
What catches itEgress firewall rules (which machines may call out, and to where) · alerts on a connection to a brand-new or odd destination · a document viewer that suddenly opens a socket. You watch the connection, because the connection is simple.
The lessonYou do not memorise viruses; you read a new one in four questions — how did it get in, how does it survive, what does it do, where does it call. Each answer points at a defence you already have. That is why the anatomy matters more than any one sample.
Where the chain breaksPatching closes Part 1. EDR catches Parts 2 and 3. Egress control and network monitoring catch Part 4. Offline backups undo Part 3 even if everything else fails. No single control is enough, and none has to be — the attacker needs all four parts to work; the defender needs to break one.

Close · back to the arsenal

You have now seen the two things the demos could not show on their own: the loop that drives the guessing, and the four parts inside the word "malware". Run the attacks again with this in mind — the browser demos or the real terminal lab — and each one is no longer a trick but a mechanism with a named defence.
