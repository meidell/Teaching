The arsenal, running in a terminal

Four of the attacks from Session 4, each one a terminal you run with a button. You watch the attack work, then the single change that stops it. Nothing here touches a real system or a network — every panel is a safe simulation running inside this page. The point to keep is not the trick; it is that the defence beside it is small, specific and known.

Why this is safe, and the rule it stands for. These panels only pretend — they compute their output inside your browser and reach nothing outside it. In real life you run tools like these only against systems you own or have written permission to test. That boundary is the professional lesson as much as any attack on the page.

1 · Guessing a weak password

One account, a password a person chose. The attacker tries a short list of the most common weak passwords. Switch the defences on and run it again: the same guesses now get locked out.

python3 demo1_passwords.py
Press Run to start the guessing.
The lessonThe guessing is identical both times. Only the victim's settings change. You cannot stop an attacker from guessing — you make each guess cost more and cap how many they get.
The defenceA slow, salted password hash; a lockout or rate-limit after a few wrong tries; and passwords long enough that a common-word list never contains them.

2 · Cracking a stolen password file

A breach hands the attacker the hashes, not the passwords. How fast they turn hashes back into passwords depends only on how the defender stored them. This measures the speed on your own device, right now.

python3 demo2_hashing.py
Press Run — it measures for a few seconds.

Now make one yourself, and crack it. A hash is the scrambled form a website stores in place of your real password: the same password always produces the same hash, but you cannot turn a hash back into the password. Type a simple password below and press Make its hash. Then press Crack the hash and watch the attacker recover the password anyway — not by reversing the hash, but by hashing a list of common passwords and comparing each result to yours.

hash & crack
Type a password above and press “Make its hash”.
The lessonSame stolen file, same attacker, same device. The defender's one choice — a fast hash or a slow salted one — moves the answer by a huge factor.
The defenceNever store passwords in the clear or under a plain fast hash. Store them salted, under a deliberately slow hash (PBKDF2, bcrypt, scrypt, Argon2), with the work factor turned up.

3 · What "a connection" actually is

One machine waits for a call; the other calls out; text passes between them. A command-and-control beacon — the thing malware opens once it lands — is, mechanically, exactly this.

The lessonThe only difference between this harmless chat and a weapon is whether the far end is wired to a shell. This demo deliberately is not — that is the line between a demonstration and an attack tool, and naming it is half the lesson.
The defenceThe malicious part is not clever; it is one outbound connection. So the defences watch the connection itself: egress firewall rules (which machines may call out, and to where) and EDR that flags a document viewer suddenly opening a socket.

4 · SQL injection — walk past the login

Type something into the username box where a login expects a name, then run it. You will see the same input two ways: glued straight into the database query, and passed as a parameter. The classic input is already filled in; try your own.

python3 demo4_sqli.py
Type a username above and press Run.
The lessonIn the first query the apostrophe ends the username and OR '1'='1' makes every row match, so the first user is logged in with no password. In the second the input is only ever data. One line of code is the entire difference.
The defenceNever build a query by pasting user input into a string. Pass input as parameters (prepared statements), so the database treats it as data and never as part of the command.

Close · put each one back on the kill chain

Each attack has a place on the chain: stolen passwords and injection are how the attacker gets in; the connection is how they stay and reach back out; the defences beside each one are where the chain breaks. You have now watched the break happen, not just read that it can.
