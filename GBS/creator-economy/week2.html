Reverse-engineer a winner

Laptop with a browser whose developer tools open (View Source, the Network tab, Disable JavaScript). One laptop per team is enough; three is better.

Session 1 produced a wall: one review site was cited by nine of fourteen rows, three platforms and four other sites followed, and the manufacturers were almost absent. This session takes the cited sources apart stage by stage, the way the pipeline sees them — what the crawler is allowed to fetch, what exists before JavaScript runs, how the page splits into passages, what structured data it declares, who links to it, when it was last changed — and turns the result into three reasons a source is quotable. Then the round that matters: find a page with the same three properties that is not cited. The reasons that survive that round are findings; the ones that do not are the material for Session 3.

The audit method: six checks, one per stage

Each check corresponds to a stage of the Session 1 pipeline, asks one question, has a procedure anyone with a browser can run, and produces one line of the audit record. The observations in the grey boxes were made on 22 October 2026 on the sources from the Session 1 wall; the room repeats them in Step 3 and may find them changed.

1 · Crawl — is the engine allowed to fetch it?

Procedure. Open https://<domain>/robots.txt. The file is a list of blocks, each starting with User-agent: and followed by Disallow: and Allow: path rules. A crawler obeys the block whose user-agent name matches it most specifically, and only that block; if there is none, it obeys User-agent: *; if there is no file, everything is allowed. For a path, the longest matching rule wins, so Allow: /reviews/ beats Disallow: / for review pages. Look for the AI tokens: GPTBot (OpenAI, training), OAI-SearchBot (OpenAI, search answers — the one that matters for ChatGPT citations), PerplexityBot, Google-Extended (a control for Gemini training, not for Google Search or AI Overviews), ClaudeBot, Bytespider (ByteDance), CCBot (Common Crawl, the corpus many models were trained on). Three other controls act after the fetch: a <meta name="robots" content="noindex"> tag or an X-Robots-Tag HTTP header removes the page from the index; nosnippet and max-snippet limit what Google may quote from it, including in AI Overviews. A file called llms.txt is a 2024 proposal for sites to summarise themselves for language models; no major engine has documented using it.

Observed · 22 Oct 2026rtings.com/robots.txt is 159 bytes: two sitemaps, one User-Agent: * block disallowing only /user_reviews/ and /admin/. Every crawler, AI or not, may fetch every review page. tomsguide.com names and blocks a list of AI crawlers (Bytespider, mistralai, cohere, ai2bot, amazonbot, diffbot, img2dataset, omgili, youbot, Applebot-Extended, meta-externalagent) but has no rule for GPTBot, OAI-SearchBot or PerplexityBot, so those three are allowed by default. soundguys.com blocks SEO crawlers (AhrefsBot, MJ12bot, DotBot, SEOkicks) and Meta's, nothing from OpenAI or Perplexity. reddit.com answered a request carrying a Googlebot user-agent string from an ordinary network with an HTML page titled Blocked — "your request has been blocked due to a network policy" — before any robots.txt was served: Reddit verifies crawlers by network, not by name, and admits licensed partners (Google and OpenAI signed content agreements with Reddit in 2024). Being cited is not the same as being fetchable by everyone.
Record: allows all · blocks some AI crawlers · blocks the engine that cited it · could not fetch.
2 · Index — what exists before JavaScript runs?

Procedure. Three views of one page. (a) View Source (Ctrl/⌘-U) is the HTML the server sent; search it for a sentence from the page. (b) In the browser's developer tools, open the command menu (Ctrl/⌘-Shift-P), run Disable JavaScript, reload: what remains on screen is what a non-rendering crawler indexes. (c) The Network tab, filtered to Doc, shows the first response's size; compare it with the size of the scripts. Googlebot renders pages in a headless Chromium (the Web Rendering Service), usually later than it crawls them and with a crawl budget, so JavaScript-built content is indexed by Google with a delay and may be indexed by other engines not at all. A text that is present only inside a JSON blob in a <script> tag is not DOM text; some engines parse such blobs, most do not. The canonical link (<link rel="canonical">) says which URL the engine should keep when several carry the same content.

Observed · 22 Oct 2026The most-cited page on the wall, rtings.com's The 4 Best Budget Noise Cancelling Headphones of 2026, fetched with a Googlebot user-agent: HTTP 200, 304 KB of HTML of which 175 KB is script, 21 script tags, and about 190 words of visible text in the HTML as served — all of it navigation labels. The review itself, the product names (31 occurrences of "Soundcore") and the comparisons are shipped inside script JSON and drawn by JavaScript. The HTML does carry a <meta name="description"> stating the page's main claim in one sentence (which model is best, and what its noise cancelling blocks), and a canonical link. The site that wins the wall is, before rendering, a nearly empty shell with one good sentence. Which engines render it is the question Step 3 cannot settle but Session 3 can design around.
Record: words of body text before JavaScript, and whether the main claim is in the raw HTML.
3 · Retrieve — how does it split into passages, and do they stand alone?

Procedure. An answer engine does not retrieve pages; it retrieves chunks, typically 100–500 tokens cut at headings and paragraph boundaries, sometimes with an overlap of a few sentences so that a claim split across two chunks survives in one of them. Each chunk is embedded and scored on its own, and a cited chunk is placed in the context window without the rest of the page. A chunk therefore has to carry its own subject: "It also lasts 40 hours" is unusable, "The Soundcore Space Q45 lasts 40 hours with ANC on, 10 more than the Sony" is a citation waiting to happen. The test for a chunk, in order: does its first sentence name its subject (no pronoun start)? does it contain a number with a unit, or a comparative ("than", "vs", "quieter", "cheaper")? does it share vocabulary with the query? A page's headings are the chunk boundaries an engine is most likely to respect, so a heading that names the product and the criterion ("Noise isolation on a train") does part of the work.

The chunker below applies that test. The sample passage is written in the style of a review page (it is not quoted from any site); paste a page's text in its place to test it. The chunk length is a slider because engines differ.

After pasting a real page (or editing the sample): how many chunks stand alone, out of how many, and what the failing ones have in common. One line.
Record: chunks that stand alone / total.
4 · Index and generate — what does it declare in structured data?

Procedure. In View Source, search for application/ld+json. Each hit is a JSON-LD block using the schema.org vocabulary: @type names the entity (Product, Review, ItemList, FAQPage, Article, Organization), and its fields are parsed directly into the index without the engine having to extract them from prose: offers.price, aggregateRating.ratingValue, datePublished, dateModified, author with a sameAs link to a profile elsewhere (an authority signal that joins the page to an entity). Google documents which types produce rich results; an answer engine uses the same fields as facts it does not have to infer. Paste the URL into Google's Rich Results Test or validator.schema.org to see what parses. Absent structured data is not a penalty; present structured data is a set of claims handed over pre-extracted.

Observed · 22 Oct 2026The rtings page carries two JSON-LD blocks, of type WebSite and Organization — the site, not the page. No Product, Review, ItemList or dates are declared. The most-cited page on the wall declares nothing about headphones in structured data; whatever makes it quotable is not this stage.
Record: the @type values found, or "none".
5 · Rank — who links to it, and who mentions it?

Procedure. PageRank and its descendants score a page by the links into it, weighted by the authority of the linking pages; the E-E-A-T evidence quality raters look for is likewise outside the page. Google's link: operator is retired, so the count has to come from a third-party index of the link graph: Ahrefs' free Backlink Checker and Moz's Link Explorer (free with an account) each report referring domains (distinct sites linking) and backlinks (individual links) from their own crawls; the two tools disagree, and both undercount, so record the tool with the number and compare sources on the same tool. Two cheaper proxies: a Google search for the site's name with -site: excluding its own domain shows unlinked mentions; a Wikipedia search shows whether the site is used as a reference there, which is the kind of reputation evidence the rater guidelines name. Record the count for the page if the tool gives it, and for the domain in any case — a new page on a linked domain inherits some of the domain's standing.

Record: referring domains (tool), and one place outside the site that mentions it.
6 · Rank and retrieve — when was it last changed?

Procedure. For queries where recency matters (Google calls the classifier query deserves freshness; "best … 2026" qualifies), the date of the content is a ranking input, and an answer engine's retriever may filter or boost by it. Find the date three ways: the visible "updated" line on the page; dateModified in the structured data; and the Wayback Machine (web.archive.org/web/*/<URL>), which shows how often the page changed and whether its title moved from "2025" to "2026" with or without new content. A page re-dated without being rewritten is a common pattern and a legitimate finding.

Record: last change, and how it was established.
What the six checks cannot seeWhich engines rendered the page, which chunks were actually retrieved, and what the model's training data contains. The audit establishes what the page offers each stage; whether a stage took the offer is inferred, not observed. A reason in Step 4 that depends on one of the unobservable facts has to say so.

The falsification round

A reason is a prediction: pages with this property are cited, pages without it are not. The cheapest test is a control — a page that has all three of the team's properties and was not cited for the Session 1 question. If such a page exists, the three reasons are not sufficient, and what the control lacks is the missing fourth reason. If no team can find one in eighteen minutes, the reasons stand for now.

Procedure

1. Search for the Session 1 question on Google and on one answer engine; list candidate pages on the same topic that did not appear on the Session 1 wall (retailers, other review sites, a manufacturer's comparison page, a forum thread). 2. Run the audit checks that correspond to the team's three reasons on the strongest candidate — only those three. 3. If it passes all three, it is a control: record it. If it fails one, that is weak evidence for the reason; try the next candidate. 4. The Operator posts the result either way.

This is the candidate fourth reason. If the candidate failed a reason instead, say which and why that supports the reason.

Terms introduced today

User-agent block · the section of robots.txt a crawler obeys: the most specific match, or *.
OAI-SearchBot / GPTBot · OpenAI's crawler for search answers, and its crawler for training data; a site can allow one and block the other.
Google-Extended · the robots token controlling Gemini training, not Google Search.
noindex · nosnippet · max-snippet · page-level controls on indexing and on how much may be quoted.
Network-level blocking · refusing a crawler by its IP range rather than by robots.txt (Reddit).
Web Rendering Service · Google's headless Chromium that executes JavaScript after crawling, with a delay and a budget.
Canonical · the URL an engine keeps for duplicated content.
Chunk · overlap · the passage unit of retrieval, and the sentences repeated between neighbouring chunks.
Stand-alone chunk · a passage with its own subject, a claim, and a number or comparison — usable out of context.
JSON-LD · schema.org · structured data embedded in the page; Product, Review, ItemList, FAQPage, dateModified, sameAs.
Referring domains vs backlinks · distinct linking sites versus individual links; the former is the authority proxy.
Query deserves freshness · the class of queries for which content date is a ranking input.
Control · a page with the same properties and a different outcome; the cheapest falsification.
Sufficient vs necessary · a control shows the reasons are not sufficient; it does not show any one of them is unnecessary.
The open claim · verdict for today
"A page can be made citable by restructuring its text alone — chunking, explicit comparative statements, statistics — with no change to who links to it."
Today's audit added a fact to the claim: the most-cited page is, before rendering, a shell whose one good sentence sits in a meta description, with no structured data about the product. If that page is cited for its text, the text the engines see is the rendered one — and Session 3's rewrite can be designed so that the same claims exist in the raw HTML, in stand-alone chunks, with structured data, on a page whose links do not change. That is the experiment.
Session 3 rewrites a page the engines currently ignore and publishes it. Of the team's three reasons, which can the rewrite change by text alone — and which engine do you expect to cite the page first, and roughly how many weeks after publication?
