Laptop with Microsoft Excel, the desktop app, open and working. The browser version cannot do tonight's keyboard work.

The session opens with a valuation model of Meridia Cold that looks finished and is wrong in twelve places: hardcodes inside formulas, inputs living in six places, a hidden plug, a sign error, no way to check anything. The autopsy

The file is a six-year model of Meridia Cold — three historical years, three forecast years, a discounted cash flow and a value per share — as it might arrive from a colleague who left. It opens in Excel with no macros and no external links.

Instructions

1. Download and open meridia-cold-v7-FINAL-2.xlsx. 2. Twenty minutes, alone. Every fault is something a formula, a cell or the layout does that a reader would not expect — a hardcode, a duplicate, a wrong reference, a sign, a unit, a hidden thing, a missing thing. 3. Record each one as cell · what is wrong, one per line. 4. Seal the list before the room compares notes.

Tools that find faults faster than reading: Ctrl+` shows every formula instead of its result; Ctrl+G → Special → Constants selects every typed number, so a number inside a calculation block is a hardcode; Ctrl+[ jumps to what a cell depends on; Ctrl+\ on a selected row highlights the cells whose formula differs from the first one; the row numbers in the margin reveal a hidden row by skipping; a number that sits left-aligned in a column of right-aligned numbers is text. Mac equivalents are in Step 3.

One per line: the cell, then what is wrong. "E5 · text, not a number" is enough.

The twelve, and what each one did to the answer

The sheet reports an enterprise value of €249.0 m, equity of €192.0 m and a value per share of €0.0048. With the same inputs and the faults removed, the model gives EV €159.4 m, equity €99.4 m and €2.48 a share. The faults did not cancel out; they never do.

1E5 FY2025 revenue is stored as text ("180.4", left-aligned). Arithmetic coerces it, so the growth row looks fine; SUM ignores it, so the historical total in C17 reads 331.2 instead of 511.6. type
2F5:G5 grow revenue by *1.067 typed inside the formula; H5 uses the input $K$8. One row, two methods — changing the assumption changes one year in three. hardcode
3F7 EBITDA margin is 0.161 in the formula, G7 uses K9, H7 uses 0.17. FY2028 EBITDA is 37.3 instead of 35.3 because somebody tested a number and left it. hardcode
4Tax: 0.25 in four formulas, the input K10 (24%) in two, a text cell saying "Tax 25%", and 25% again on the Notes sheet. Four homes for one number, three values. duplicate
5H12 FY2028 capex is =G12 — a copy of the previous year instead of the row's formula. Capex stops growing with revenue in the year that drives the terminal value. reference
6F14 free cash flow adds capex: =F11+F8+F12-F13. FY2026 cash flow shows 40.2 against 9.6; it alone adds about €28 m to the present value. sign
7Row 15 is hidden and holds 2.5 in H15, which H14 adds to FY2028 cash flow. A plug that lifts the terminal value by 11%. The Notes sheet knows: "unhide adj row before sending??" hidden
8C19 holds the WACC, 8.5%, and nothing refers to it. Every discount formula uses 0.09, typed; D19 says "9% per CFO email". The visible input is not the one in use. hardcode
9H22 discounts FY2028 with ^2; it is year 3. reference
10Net debt is 57 in C26 and 60.0 on the Notes sheet, "bank statement 31/12". Two values, no link, no date on the one in use. duplicate
11C28 shares are in thousands (40,000); equity is in €m; C29 divides one by the other. €0.0048 a share is a unit error, not a valuation. units
12No check anywhere: nothing on the sheet says whether the statements tie, the sources match the uses, or the timeline is consecutive. The file name says "FINAL (2)" instead. no check
The patternNot one of the twelve is an arithmetic mistake. Each is a structural habit: a number where a reference belongs, an input with more than one home, a row that differs from its neighbours, a value whose unit is not written next to it, a thing nobody can see. A reader cannot find them by checking the arithmetic; they are found by checking the structure — which is what the conventions in Step 3 exist for.

Build I · Meridia Cold, from a blank workbook: the skeleton

Meridia Cold SL is a temperature-controlled logistics operator headquartered in Barcelona: fourteen cold-storage warehouses in Spain, France and Italy, about €180 m of revenue, most of it on multi-year contracts with food producers and retailers. Two parties want to buy it — Boreal Logistics, a listed strategic acquirer, and Arco Partners, a private-equity sponsor — and in presentation week each team advises Meridia's board which bid to take. Tonight the model the colleague should have built is built properly, in three parts: the skeleton, the forecast, the valuation. It ends on the number the broken file should have shown.

🎤 On the screen · 8 min · the four rules the broken file broke
  1. Inputs, calculations, outputs — separated. Every number a human types lives on Inputs; Calc holds formulas only; the Cover shows what the reader needs. Show it: Ctrl+G → Special → Constants on a Calc sheet must select nothing. In the broken file it found 0.09, 0.25, 0.17 and 1.067 inside formulas.
  2. One input, one home. The tax rate had four homes and three values; net debt had two. An assumption is typed once, with its unit beside it, and referenced everywhere else.
  3. Colour by what a cell is. Blue = typed input · black = formula on the same sheet · green = link to another sheet · red = external link or warning. A blue cell on Calc is a hardcode you can see from across the room.
  4. Checks are rows, not opinions. A check is a difference that must be zero (=ABS(a−b)), all checks roll up into one master cell, and the cover says OK or ERROR. A model whose master check is not 0 is not sent to anyone. The broken file had none — its name, "FINAL (2)", stood in for one.

Then build the first five items below live, on the projector, while the room builds with you. Time runs across; the same column is the same year on every sheet.

Build II · The forecast: six drivers, one formula per row

A forecast is not three columns of typed numbers. It is a handful of drivers — growth, margin, reinvestment — on the Inputs sheet, and one formula per row on Calc that turns them into the next three years. Change a driver and every year moves; that is the whole point, and the broken file could not do it.

🎤 On the screen · 8 min · drivers, flags and the dollar sign
  1. Why drivers. A buyer does not argue about FY2027 revenue; they argue about growth. Put the arguable thing in one blue cell and the debate becomes one cell.
  2. The period-flag formula. One formula must serve both the actual years and the forecast years, or the row has two formulas and fails Ctrl+\. The flags from Build I do it: = actual flag × the input + forecast flag × the calculation. In an actual year the forecast flag is 0 and the calculation vanishes; in a forecast year the reverse.
  3. The dollar sign, once and for all. In =F$5*Inputs!F8+F$6*E8*(1+Inputs!$C$18) the row of the flag is frozen (F$5), the year moves with the column, and the driver is frozen completely ($C$18). Type it in F, press F4 to cycle the anchors, then Ctrl+R to fill right. If one cell in the row needs a different formula, the model is wrong, not the row.
  4. Free cash flow, unlevered. NOPAT + D&A − capex − increase in working capital. Cash the business produces before anyone is paid — lenders or shareholders. The broken file added capex in FY2026; here the sign is decided once, on the cover, and formulas subtract.
Inputs — the drivers

Single values in column C, blue, with the unit in B: C18 Revenue growth 6.7% · C19 EBITDA margin 16.1% · C20 D&A growth 5.0% · C21 Capex, % of revenue 8.0% · C22 NWC, % of the revenue increase 10.0%. FY2025's own growth and margin were 5.5% and 16.1%; the plan assumes FY2024's growth again.

Build III · The valuation: from free cash flow to €2.48 a share

The last part turns the forecast into a value: discount each year's free cash flow at the cost of capital, add the value of everything after FY2028, take away what is owed to lenders, divide by the shares. Then ask the model the question a buyer would — how much of this value is one assumption?

🎤 On the screen · 8 min · discounting, the terminal value, the equity bridge
  1. Discounting. A euro in FY2027 is worth 1 ÷ (1 + WACC)² euros today. The discount period comes from the timeline (year − last actual year), never from a typed exponent — the broken file wrote ^2 for year 3.
  2. The terminal value. Three forecast years cannot hold a business that lasts decades. After FY2028 the cash flow is assumed to grow at g for ever: TV = FCF₂₀₂₈ × (1 + g) ÷ (WACC − g), valued at the end of FY2028 and discounted with FY2028's factor. It only works if WACC > g — that becomes a check.
  3. Where the value sits. In this model the terminal value is about 84% of the enterprise value. The three years you forecast carefully are 16%; the rest is two numbers, WACC and g. That is why the sensitivity table below matters more than any single figure.
  4. The equity bridge. Enterprise value belongs to lenders and shareholders together; equity = EV − net debt at the valuation date; per share = equity ÷ shares, in the same unit. The broken file divided €m by thousands of shares.

Teams and roles

Teams of three, fixed for the term; the final presentation is the team's, the participation mark is each member's own, and the file each student builds is their own. In each session every member takes one of three roles; the roles rotate:

  • Builder: hands on the keyboard for the team's shared decisions; responsible for the team producing its file.
  • Auditor: reads formulas, not results; runs the constants audit and the check rows on the Builder's file before anything is handed in.
  • Presenter: explains the model's result and the three assumptions it depends on, in plain sentences, to whoever asks.

Terms introduced today

Precedent · dependent · a cell a formula reads; a cell that reads it. Ctrl+[ and Ctrl+].
Relative · absolute · mixed reference · A1 · $A$1 · A$1 / $A1; F4 cycles them.
Hardcode · a number typed inside a formula or on a calculation sheet; invisible to tracing.
Number stored as text · a string that arithmetic coerces and SUM ignores.
Inputs · Calc · Outputs · the three-part layout; constants live only in the first.
Period flag · a 1/0 row marking actual versus forecast columns; turns IF-logic into multiplication.
One formula per row · written once, filled right; Ctrl+\ audits it.
Blue · black · green · red · input · formula · link to another sheet · external link or warning.
Check · a difference that must be zero, with a tolerance; aggregated into a master check on the cover.
Group, not hide · collapsible rows the reader can see.
Driver · an assumption in one blue cell (growth, margin, capex %) from which a forecast row is computed.
Unlevered free cash flow · NOPAT + D&A − capex − increase in working capital; cash before lenders and shareholders.
Discount factor · 1 ÷ (1 + WACC)ⁿ, with n taken from the timeline, never typed.
Terminal value · FCF × (1 + g) ÷ (WACC − g): everything after the forecast; here 84% of the enterprise value.
Enterprise value · equity bridge · the value of the business; minus net debt is the value of the shares.
Data table · Goal Seek · Excel's What-If tools: a grid of answers for two inputs; the input that delivers a target answer.
Open question · for Session 2
"Of the twelve faults in the broken model, how many would a check block catch — and how many can only be caught by a convention?"
A check compares two computed numbers; it catches a model that does not tie (faults 1, 6, 7, 9, 11 would move a check somewhere). A hardcode or a duplicate input (2, 3, 4, 8, 10) keeps every check at zero and is caught only by the layout and colour discipline.
