Build I · Lookups: find a figure by what it is, not where it is

A model is read by people who want one figure: EBITDA in FY2027, or net debt in the last actual year. Last week's net-debt cell already found its value with INDEX/MATCH on the year. Tonight that becomes a habit, and the cover gets a snapshot that shows any year's revenue, EBITDA and free cash flow. First, the reason not to use the function most people learned first.

🎤 On the screen · 8 min · what a lookup actually stores
  1. VLOOKUP stores a position. =VLOOKUP("EBITDA",$A$8:$K$22,10,FALSE) finds the row whose first cell is "EBITDA", then returns the 10th column of the range. The 10 is a typed number inside a formula: a hardcode. Excel adjusts cell references when columns are inserted or deleted, but it never edits a constant. Insert a column inside the range and the 10 points at a different year, without any error.
  2. The fourth argument decides the search. FALSE (or 0) means exact match: Excel scans down the first column until it finds the value, and returns #N/A if it does not. Left out, it means approximate match, which assumes the first column is sorted ascending and binary-searches it. On a column of labels, that can return a neighbouring row without any error. In a model, a lookup is always exact.
  3. INDEX/MATCH stores two questions. MATCH("EBITDA",$A$8:$A$22,0) returns the position of the label in its column, here 3. MATCH(2027,$F$4:$K$4,0) returns the position of the year in the timeline, here 5. INDEX($F$8:$K$22,3,5) returns the cell at that row and column. Nothing is counted by hand. An inserted column shifts the ranges, and both MATCHes find the same label and year again.
  4. Failing loudly is the good outcome. Rename the label to "EBITDA (€m)" and both formulas return #N/A. That is correct behaviour: an error you can see beats a plausible wrong number. It is also why the snapshot below links its labels from Calc instead of retyping them. (Excel 365 has XLOOKUP, which does the same job in one function. INDEX/MATCH works in every version a colleague might open the file with.)

The same structure in another business · a hotel's rate card

A Geneva hotel keeps its room rates in a grid: room types down column A (Standard, Superior, Junior suite, Suite in A5:A8), seasons across row 4 (Low, Mid, High, Festival in C4:F4). The booking sheet needs the rate for a Junior suite in High season. =VLOOKUP("Junior suite",$A$5:$F$8,5,FALSE) works, until revenue management adds a "Shoulder" season column between Mid and High. Then the 5 points at Shoulder.

The robust version is =INDEX($C$5:$F$8,MATCH("Junior suite",$A$5:$A$8,0),MATCH("High",$C$4:$F$4,0)). MATCH returns 3 for the room and 3 for the season, and both are found again after any insert. The industry is different and the lookup is the same: one label down, one label across.

Build II · The scenario switch: three cases, one cell

Last week the five drivers were typed straight into C18:C22. If a case changes, someone retypes them and the previous case is gone. Tonight the cases sit side by side in a scenario table, each one typed once, and the cells the model reads become a live column that copies whichever case one selector cell names.

🎤 On the screen · 8 min · CHOOSE, the live column, names
  1. CHOOSE returns its n-th argument. =CHOOSE(2,C30,D30,E30) returns D30. The index is truncated to a whole number, so 2.7 behaves as 2. An index below 1 or above the number of options returns #VALUE!. CHOOSE can pick from cells that are not next to each other, which is why the syllabus names it for scenario switching. =INDEX(C30:E30,2) does the same here, and a fourth case only means widening the range.
  2. The live column. C18:C22 stop being inputs. Each becomes =CHOOSE(Scenario,C30,D30,E30), black, because it is now a formula. The blue cells are the scenario table. Calc did not change: it still reads C18:C22, so not a single model formula is edited.
  3. Names. A name is a workbook-wide label for an absolute reference: WACC means =Inputs!$C$24. A formula reads as its logic, =F$6/(1+WACC)^F20, and Ctrl+[ still traces it. The risk is that a name hides where it points, and the Name Manager can hold stale names that give #REF!. The rule: name a handful of single-cell inputs, never a block of calculations, and paste the list of names onto the cover.
  4. A data table across the cases. A one-variable data table with the selector as its input cell runs the whole model three times and prints EV and value per share for each case side by side. Excel requires a data table's input cell to be on the same sheet as the table, so the table lives on Inputs, next to the selector. (Last week's WACC × g grid belongs there too, for the same reason.)

Build III · The audit block: errors stop the model, warnings ask a person

Last week's Checks sheet held six differences that must be zero. That was a start. Tonight it becomes an audit block with two kinds of check and a master that cannot be fooled.

🎤 On the screen · 8 min · what an audit block contains
  1. Errors and warnings are different things. An error check tests something that must be true: the timeline is linked, the actuals carry over, WACC exceeds g, the selector is 1, 2 or 3. If one fails, the model is wrong, and the cover says ERROR. A warning tests something that is merely unusual: a margin above 30%, a terminal value above 85% of EV. It can be legitimate, so it is counted and shown, and it never turns the cover red. A model that flags every oddity as an error trains its reader to ignore the flag.
  2. Four families of error check. Integrity: two routes to the same number agree (the actuals carried over, PV computed two ways). Type: ISTEXT over the typed inputs catches a number stored as text, last week's fault 1. Structure: ISFORMULA catches a number typed over a formula on Calc (Excel 2013 or later). Switch: the selector is valid, and the live column equals the case it names.
  3. An error value is a failed check. If the selector is 4, CHOOSE returns #VALUE!, the error flows into the checks, and MAX of a range that contains an error is itself an error. The master then shows neither 0 nor 1. Wrapping it, =IFERROR(IF(MAX(…)<0.001,0,1),1), turns "cannot tell" into ERROR, which is the only safe reading.
  4. A check outside the master's range is decoration. Inserting rows inside a range grows it. Inserting them just below, as you will do now, does not: MAX(C5:C10) stays MAX(C5:C10). Every new check therefore ends with editing the master's range. Some modellers leave a blank row inside the range for exactly this reason.

Break it on purpose

An audit block that has never caught anything is untested. Within your team, the Auditor plants one error in the Builder's v02 while the Builder looks away; the Presenter keeps time. The Builder then has six minutes to find it, starting from the cover. Then swap and repeat with a new card. Work on a copy: File → Save a Copy as …-v02-sabotage.xlsx.

Rules

1. Select case 1 before planting. 2. Plant exactly what the card says, nothing else. 3. The Builder may use every tool from last week (Ctrl+`, Ctrl+G → Constants, Ctrl+\, Ctrl+[) and the audit block. 4. Record what found it: a check row, a warning, a tool, or nothing.

Error check · Warning only · Nothing (a convention finds it)
Last week's open question, answeredOf nine planted errors, five turn the cover to ERROR, two raise only a warning, and two pass every check: a constant inside a formula and a formula copied from the neighbour. Those are the faults the audit block cannot see by construction. A check compares numbers, and both errors leave plausible numbers. They are found by the conventions (Ctrl+\, one formula per row, no constants in formulas), which is why the conventions came first.

Terms introduced today

VLOOKUP column index · a typed position inside the formula; an inserted column moves it silently.
Exact vs approximate match · FALSE / 0 scans for the value or returns #N/A; omitted, it binary-searches a column assumed sorted.
INDEX/MATCH · MATCH returns a position, INDEX returns the cell at it; two MATCHes make a two-way lookup.
Data validation · a cell that accepts only listed values; pasting can bypass it, so a check still tests the cell.
Evaluate Formula · steps through a formula one function at a time.
Scenario table · live column · every case typed once, in blue; the cells the model reads copy the selected case.
CHOOSE · returns its n-th argument; n is truncated; outside 1…n it returns #VALUE!.
Named range · a workbook-wide label for an absolute reference; for a few single-cell inputs only.
Data table input cell · must be on the same sheet as the table; a one-variable table on the selector compares all cases.
Error check · warning · must be true, turns the cover to ERROR · merely unusual, is counted and shown.
ISTEXT · ISFORMULA · type and structure checks: text among inputs, numbers typed over formulas.
IFERROR on the master · an error value inside a check counts as a failed check.
Open question · for Session 3
"Next week the balance sheet will not balance the first time. Which check would tell you where it breaks, not only that it breaks?"
A single "assets − liabilities − equity = 0" check says that something is wrong. A check per year says when it first goes wrong, and a check that the cash on the balance sheet equals the cash flow statement's closing cash says which statement to look at.
