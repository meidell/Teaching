🎤 9:25How an AI writes code

A web page, three layers

The browser receives a text file and runs it. That file mixes three languages, each with its own job:

  • HTML — the structure: a heading, a field, a button, a list. <button>Send</button>
  • CSS — the look: colours, sizes, layout on a phone. button { background: teal; }
  • JavaScript — the behaviour: what happens when you click. button.onclick = send;

Today all three fit in one single file. That is the simplest form of an application: no server of your own, nothing to install.

Where the data lives

A page on its own forgets everything when it is closed, and every user has their own copy. For a message written on one phone to appear on another, you need a shared place: a database on the Internet.

We use Firebase Realtime Database (Google), on its free plan. It stores one big JSON tree — names and values, nested:

{ "messages": {
    "-Nx81a": { "author": "Léa",  "text": "Hello!", "ts": 1793084400000 },
    "-Nx81b": { "author": "Omar", "text": "Hi",     "ts": 1793084460000 } } }

Every branch has a web address. The page talks to it with fetch(), over HTTP, the protocol of the web: GET to read, POST to add, PATCH to change, DELETE to remove. That is called a REST API. Prompt 2 in the workshop gives the AI exactly these four rules.

What the model actually does

An assistant such as Claude or ChatGPT is a large language model. It produces its answer one piece of a word (a token) at a time, computing at each step which token is most likely after everything that came before — your prompt included. It learned these probabilities from an enormous amount of text, including millions of pages of public code.

Three practical consequences:

  1. It is very good at what is common. A form, a list, a button that sends data: it has seen these patterns thousands of times.
  2. It does not know what you do not tell it. Your database address, what “nice-looking” means to you, the rule that refuses certain writes: if it is not in the prompt, it guesses. Hence long, precise prompts.
  3. It can produce wrong code that looks right — a function that does not exist, a condition the wrong way round. It does not run the code before answering. You run it, look, and report the gap back to it.
Chat or agent

With a chat assistant, the loop goes through you: it writes, you copy, you run, you paste the error back to it. That is what we do today — free, in the browser, and you see every step.

An agent (Claude Code, Cursor, GitHub Copilot in agent mode…) runs the loop on its own: it creates the files on the computer, runs the code, reads the errors, fixes them, tries again, and stops only when the result passes the tests. These are usually paid tools, built for projects with many files.

🎤 Live demonstration

An agent gets a single instruction: “Build a screen that shows this morning’s poll results live, read from the database at this address.” The room follows on the screen what it does — the files it creates, the errors it hits, the fixes it makes — until the screen works.

🛠 9:50Workshop 1 · The first version

What you do, in order
  1. Get into twos or threes, around one laptop.
  2. On that laptop, open the workshop (the link or QR code at the top of this page).
  3. Workshop step 1: type a team name and wait for the green ✓.
  4. In another tab, open a free AI (Claude, ChatGPT, Gemini or Le Chat) and sign in.
  5. Workshop step 2: choose an idea from the list below, or describe your own. Click Copy on prompt 1, paste it into the AI, send it.
  6. Copy the AI’s whole answer. Workshop step 3: paste it into the big box, click ▶ Run.
  7. Try the three features. If one does not work: copy prompt 3, replace the [square brackets] with what happened, send it to the AI, paste its new answer in step 3, ▶ Run.

Choose a small idea: one sentence, three features. A small app that works beats a big app that is broken.

Done when: the three features work in the workshop preview (the data still disappears on reload: that is normal at this stage).

Four rules that save time
  • One request at a time. Three changes in one prompt, and you will not know which one broke the app.
  • Always the complete file. A piece of code to “insert somewhere” is the number one source of errors.
  • Describe the gap, not the solution. “I clicked Send, nothing appears, here is the error” works better than “fix the send function”.
  • A version broke the app? The workshop’s Versions menu brings back the previous one.

🛠 10:20Workshop 2 · The database

What you do, in order
  1. Workshop step 2: click Copy on prompt 2. Paste it into the same conversation with the AI and send it. It already contains your team’s address in the database.
  2. Copy the new answer. Step 3: delete the old code, paste the new one, ▶ Run.
  3. In your app, add something. Look at the black panel: a green line = the database accepted it; a red line with 401 = the database refused it → prompt 3.
  4. Step 4: click ↻ Re-read the database. What you added appears.
  5. Step 5: click 🚀 Publish, open the link on a phone, add something on the phone. On the computer, it appears within ten seconds.
Reading a refusal

HTTP 401 means: the database refuses this write at this place. The database rules only allow writing to one specific item of your branch (…/messages/<id>), never to the whole branch — otherwise one single request could wipe all your work. Prompt 2 tells the AI so; if it forgets, send it the error with prompt 3.

Done when: an item added on one device appears on the other within ten seconds, and is still there after a reload.

🎤 11:30What can go wrong

What you have just seen for yourselves
  • This morning’s database is open. Anyone who knows the address can read and write any team’s branch — you could do it. A real app needs authentication (who are you?) and rules on the database side (what are you allowed to do?). The AI does not add them unless you ask.
  • All the code of a web page is public. Right-click → “View page source”. A secret key, a password or a confidential price written into the page can be read by every visitor.
  • User text is dangerous. Displayed with innerHTML, a message containing code is executed for everyone who reads it (an XSS attack). That is why prompt 2 requires textContent. In the workshop, each app also runs in an isolated sandbox.
  • Personal data has a law. In Switzerland the nFADP, in the EU the GDPR: names, phone numbers or addresses in a database need a reason, clear information for the people concerned, and hosting you can justify.
  • Code that works is not code that is right. An expenses calculation can show a plausible, wrong result. Check the numbers by hand on a small example.
Before handing an app to real users
  1. Who can read what, who can write what — and does the database really enforce it?
  2. No secret in the page’s code.
  3. Personal data: which, why, for how long, where.
  4. Every feature tested, including with absurd input (empty, very long, emojis, two quick clicks).
  5. Someone who can read code has reviewed it — the AI can help, it does not replace a review.

Carrying on by yourself

Your own Firebase database, free, in ten minutes
  1. On console.firebase.google.com, sign in with a Google account and create a project.
  2. In the Build menu, choose Realtime Database → Create database, a region in Europe, and test mode.
  3. Copy the address shown above the data (it ends in firebasedatabase.app) and put it in place of BASE in your file.

Test mode lets anyone read and write, and Firebase closes it by itself after a few weeks. For an app that lasts, ask the AI to help you write security rules and add a login.

Putting your file online

Your app’s code is in the workshop (step 3): copy it into a file called index.html. Opened with a double-click, it works on your computer. For a public address, there are free hosts for static pages — GitHub Pages, Netlify, Cloudflare Pages, or Firebase’s own hosting. Ask the assistant to guide you step by step for the one you choose.
