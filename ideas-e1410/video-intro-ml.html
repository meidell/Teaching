Before you watch

Two piles of data, never one

Machine learning splits your data in two. The model is fitted to the training pile — it adjusts itself until it does well there. It is then judged on the testing pile, which it has never seen.

That split is not a technicality. It is the entire discipline. A model that has memorised the training data will score beautifully on it and be worthless in production, and the only way to detect that is to hold data back.

Fitting well is not the goal — predicting well is

Josh Starmer's second point is the one project managers underestimate: a more complicated model fits the training data better by construction. A wiggly enough line passes through every point you own.

So "our new model fits the data better" is not evidence of anything. The question is whether it predicts better on data it has never met, and that is a different measurement.

What you should be able to say afterwards
Takeaways
  • Which pile is that number from? When a team reports accuracy, the first question is not "how high?" but "measured on what?" Training-set accuracy is a description of the past, not a prediction about the future.
  • Complexity is not progress. A model that fits better may generalise worse. You will meet this again as bias and variance.
  • Held-out data is a project asset. It has to be planned for, ring-fenced and kept clean — that is a line in the work breakdown, not an afterthought.
On MekongPay → Your team reports that the fraud model is 98% accurate. Before that number means anything you need to know it was measured on transactions the model never trained on — and that those transactions came from a period the model was not tuned against. If the answer is vague, the number is decoration.
