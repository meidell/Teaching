Before you watch

Splitting once is a lottery

If you hold back one quarter of your data as the test set, your result depends on which quarter you happened to pick. Pick an easy quarter and the model looks good. Pick a hard one and the same model looks poor.

Cross validation removes the luck. Divide the data into blocks — four, ten, however many — and run the whole exercise repeatedly, each time using a different block as the test set and the rest as training. Every block gets to be the test set exactly once, and you average the results.

It chooses the method; it is not the finished model

This is the point most often missed. Cross validation is how you compare candidates — this method versus that one, this setting versus that one. It answers "which approach should we commit to?"

Once you have chosen, you fit the final model on the data you have. Cross validation is the selection process, not the product.

What you should be able to say afterwards
Takeaways
  • Every candidate costs k runs, not one. Ten-fold cross validation on four candidate methods is forty training runs before anyone has chosen anything. That is a schedule fact, and it belongs in the plan.
  • This is the honest answer to the COO. "How long until the model is ready?" cannot be answered because the number of candidates you will need to try is itself unknown at the start.
  • It is also the buffer argument. The uncertainty is real and structural, so the slack goes where the experimentation is — not padded onto the end of the chart.
On MekongPay → MekongPay has six months. If the team evaluates four modelling approaches under ten-fold cross validation, that is forty full training-and-evaluation cycles before a single approach is selected — and the answer may be "none of these are good enough yet." This is exactly the work that the buffer after data preparation is paying for.
